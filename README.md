# 畅观博物馆 · 无障碍参观预约与接待系统

面向博物馆无障碍服务的单页应用（前端项目，无需后端服务）。把**观众预约、无障碍路线、轮椅/车位等设备、讲解员/志愿者排班、入馆核验、展厅接应、突发处置、参观后回访**放在**同一条参观服务记录**中，兼顾文化服务体验与现场安全。

技术栈：**React 18 + TypeScript + Vite + Zustand（localStorage 持久化）+ React Router**，无 UI 组件库依赖。

## 功能与需求对应

### 观众预约（手机端 `/book`）
- 填写参观日期、预计到馆时间、人数。
- 需求开关：**是否使用（自带）轮椅、是否借用馆方轮椅、是否需要手语讲解、是否需要慢速讲解、是否有老人/儿童同行、是否需要近距离无障碍车位、能否长时间站立**。
- 填写时右侧**实时给出"路线可行性预估"**：可安排展厅数、总距离、总时长、时段、轮椅库存、车位、陪同排班与各项提示。

### 可行路线生成（`src/lib/planner.ts`）
路线同时考虑 5 类约束：**展厅覆盖 × 观众体力 × 设备可用 × 展厅拥挤 × 工作人员接应能力**。
- 馆区图模型：B1 特展层、F1 大厅服务台、F2 古代馆、F3 近代/自然馆；节点含展厅、电梯、坡道、休息点、无障碍卫生间、无障碍车位、服务台。
- Dijkstra 寻路（电梯故障时自动剔除故障电梯、全程绕行备用电梯；双梯全停时跨层展厅安全跳过且不崩溃）。
- 每段路线提示：**距离、最大坡度、步行/乘梯耗时、预计到达时间、休息点、无障碍卫生间位置、需要协助的动作**。
- 按体力调整步速与步行预算（轮椅 / 慢速 / 老人 / 不能久站），低体力路线自动插入休息点与卫生间途经点。
- 拥挤度按开馆双峰（10:30、14:30）+ 展厅热度确定性测算，并支持工作人员人工覆盖；**过度拥挤展厅自动避让**。
- 临时闭馆展区自动移出；闭馆时间/返回缓冲不足的展厅不排入。
- 轮椅库存、无障碍车位、讲解员/志愿者排班（技能：手语/慢速/轮椅协助、班次、请假、时段冲突、楼层接应位容量）统一核算并给出降级方案。

### 入馆当天（馆内平板工作台 `/ops`）
- **服务台**：核验预约、办理入馆、借出/归还轮椅（记录资产编号与时间）、确认车位、安排/人工改派讲解员或志愿者。
- **展厅工作人员**：在"今日接应任务看板"按时间看到每组观众的**预计到达时间、人数、是否轮椅、拥挤度与需要协助的节点**；观众离厅时一键标记进度，故障后剩余路线以该厅为续览起点即时重算。
- **现场调度**：一键设置电梯临时故障（可选择对观众公示的停用原因）、展区临时闭馆、展厅拥挤度、讲解员临时请假、轮椅报修/归库；**变更后所有相关预约的路线、排班、设备与提示自动重算**（路线版本递增并写入服务记录）。
- 支持处置：观众迟到、观众身体不适（自动缩减路线、加密休息）、陪同人临时增加、突发协助（坡道推行、电梯接应、医护联系、卫生间引导等自定义记录）。

### 电梯故障后的路线重算（观众已到馆场景）
观众已入馆、通往重点展厅的电梯停用时，观众端（`/visit/:id`）会出现"现场路线调整通知"面板，**不是简单提示服务取消，而是给出完整重算结果与选择**：

- **无障碍路线重算**：自动剔除故障电梯、改走备用电梯（双梯全停时跨层展厅安全跳过不崩溃），续览从观众最后离厅的展区继续，不折返、不重复。
- **四项关键结果**：预计延误时间（含候梯/绕行，分钟）、步行距离变化（缩短/增加米数）、**是否需要工作人员推行**（轮椅×坡道坡度≥6%×绕行距离给出推行依据，并安排黄袖标工作人员在备用电梯厅接应）、保留的原计划/重点展厅数量。
- **失效原因公示**：每部故障电梯的具体停用原因与抢修预期、改乘哪部备用梯；每个无法到达的展厅逐条说明原因（电梯不可达/体力预算/闭馆时间/接应位等）。
- **可替代展区**：优先改排同楼层、无需再跨层的展厅，并列出其重点展品；观众还可勾选候选展区或在预约时标记"最想看的重点展厅"，重排立即生效。
- **新参观收益**（减少"服务被随意取消"的感受）：保留哪些重点展品、替代展区能看到什么、步行是否缩短、延误多少、**无法到达展厅改发线上云讲解编号（CLOUD-*，7 天内回看）**、改期可快速入馆、工作人员主动推行等。
- **观众三种选择，服务台保留处理结果**：① **调整参观顺序**（接受新路线继续）；② **改期再来**（选日期，状态回到已预约、在借轮椅自动归还、今日进度与云讲解码保留在同一服务记录）；③ **取消今日现场讲解**（无障碍路线/轮椅/物理协助保留，讲解全部改线上云讲解；电梯恢复后服务台可一键恢复讲解）。
- 选择以 `recovery`（故障处置）事件写入同一条服务时间线；服务台在 `/ops` 看到待受理项，一键"确认受理并告知观众"（受理人+时间留痕），观众端同步显示已受理。

### 同一条服务与服务延续（观众端 `/visit/:id`）
- 馆区平面图高亮实际路线（电梯、坡道、休息点、卫生间、闭馆/故障、拥挤点）。
- 完整分段路线时间线（距离、坡度、休息点、卫生间、预计到达）。
- 观众可手机自助报备迟到、身体不适、给服务台留言。
- **服务记录时间线**：预约前（book/排班/车位）、入馆中（核验、轮椅借还、路线调整、协助、突发）、参观后（归档、反馈偏好）全程留痕；反馈偏好用于"下次接待延续"。
- 数据通过 Zustand persist 保存在浏览器 localStorage，刷新不丢失。

## 目录结构

```
src/
  types.ts              领域模型（预约/路线/设备/人员/服务事件/故障重算分析/处置决定）
  data/museum.ts        馆区节点图、通道/电梯/坡道、展厅（重点展品+云讲解码）、库存、排班
  lib/planner.ts        路线规划引擎：寻路、拥挤度、库存/车位/排班约束、突发重算与故障对比分析
  store.ts              Zustand store：全链路动作（含观众处置/服务台受理/现场进度）+ 持久化 + 演示数据
  components/           馆区平面图、路线时间线、故障重算面板、通用 UI
  pages/                首页(手机端我的预约) / 预约 / 参观详情 / 馆内工作台
scripts/                规划场景断言、store 冒烟、SSR 渲染冒烟
Dockerfile / nginx.conf / docker-compose.yml   一键启动
```

## 本地启动

### 方式一：Docker 一键启动（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

多阶段构建：Node 22 构建静态产物 → nginx 1.27 托管（含 SPA history 回退），容器带健康检查。

### 方式二：本地开发（Node 22）

```bash
npm install
npm run dev          # http://localhost:5173 ，热更新
npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览生产构建
```

> 若本机 npm 缓存目录权限异常（EACCES），可指定本地缓存：
> `npm install --cache ./.npm-cache`

- 观众手机端：首页 `/`、预约 `/book`、参观详情 `/visit/:id`（可用浏览器 DevTools 切手机视口）。
- 馆内平板端：`/ops`（建议横屏/平板视口）。

### 手动验证清单

1. 打开 `/book`，勾选"借用轮椅 + 慢速 + 老人 + 车位 + 不能久站"，并点选 1–2 个"最想看的重点展厅"，观察右侧可行性预估随填写变化。
2. 提交预约，进入详情页查看平面图高亮与每段路线的**距离/坡度/休息点/卫生间/预计到达**。
3. 进入 `/ops`：
   - 点"**1号客梯 → 点击设为故障**"，在下拉里切换"公示原因"；回到观众详情页确认顶部出现"**现场路线调整通知**"：失效原因、预计延误、步行变化、是否需要推行、保留展厅、替代展区、云讲解码与新参观收益，路线改走 2 号梯、版本升 v2、服务记录出现"路线调整"；
   - 在详情页依次点"**按新顺序继续参观 / 改期（选明天）/ 改为线上讲解**"，确认每次选择都出现在服务记录；再回 `/ops` 点"**确认受理并告知观众**"，观众端显示受理人与时间；
   - 点"**⑤ 现场参观进度**"中已完成的展厅，确认该厅从接应看板消失、观众端路线变为"续览起点：××馆之后"且不折返；
   - 把第二部电梯也设为故障，确认跨层展厅全部安全跳过、每个厅给出失效原因并配发 CLOUD-* 云讲解码、页面不崩溃；
   - 点某讲解员"**设请假**"，确认相关预约自动改派并给出降级提示；
   - 连续点"**轮椅报修**"直到库存为 0，确认借用预约出现排队调剂提示；
   - 把自然探索馆拥挤度设为"过度拥挤 88%"，确认路线避让该厅；
   - 对选中服务设置"**迟到 30 分钟**""**身体不适**""**临时增加陪同 +2**"，确认接应时间顺延、展厅缩减、队伍人数更新；
   - 点"核验入馆 → 借出轮椅 → 开始参观 → 突发协助 → 归还轮椅 → 完成归档"，确认所有动作都出现在该服务的**同一条记录时间线**中。
4. 归档后在详情页底部填写反馈，回到首页确认该偏好出现在历史服务记录中（供下次延续）。

## 已执行的验证结论

- ✅ `npm run build`：TypeScript 严格模式 0 错误，Vite 生产构建成功（60 个模块，产物正常生成）。
- ✅ `npm test`：62 + 42 + 39 = **143 项断言全部通过**。
- ✅ `npm run preview` 启动后 `curl http://localhost:5173/` 返回 `200` 与应用 HTML，`/visit/任意路径` SPA 回退返回 `200`。
- ⚠️ 当前开发环境**未提供 Docker 守护进程**，因此 Dockerfile/Compose **未能在本环境实际构建镜像**；构建流程（多阶段 + nginx SPA 回退）已按标准方式编写，请在装有 Docker 的环境执行 `docker compose up --build` 做最终确认。
- 说明：应用为纯前端演示，排班、拥挤度、库存为内置确定性模型与本地数据；真实接入时可将 `src/lib/planner.ts` 的输入与 `src/store.ts` 的动作替换为后端 API，页面与状态结构无需改动。
