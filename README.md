# 畅观博物馆 · 无障碍参观预约与接待系统

面向博物馆无障碍服务的单页应用（前端项目，无需后端服务）。把**观众预约、无障碍路线、轮椅/车位等设备、讲解员/志愿者排班、入馆核验、展厅接应、突发处置、参观后回访**放在**同一条参观服务记录**中，兼顾文化服务体验与现场安全。

技术栈：**React 18 + TypeScript + Vite + Zustand（localStorage 持久化）+ React Router**，无 UI 组件库依赖。

## 功能与需求对应

### 观众预约（手机端 `/book`）
- 填写参观日期、预计到馆时间、人数。
- 需求开关：**是否使用（自带）轮椅、是否借用馆方轮椅、是否需要手语讲解、是否需要慢速讲解、是否有老人/儿童同行、是否需要近距离无障碍车位、能否长时间站立**。
- 填写时右侧**实时给出"路线可行性预估"**：可安排展厅数、总距离、总时长、时段、轮椅库存、车位、陪同排班与各项提示。

### 可行路线生成（`src/lib/planner.ts`）
路线同时考虑 5 类约束：**展厅覆盖 × 观众体力 × 设备可用 × 展厅拥挤 × 工作人员接应能力**。
- 馆区图模型：B1 特展层、F1 大厅服务台、F2 古代馆、F3 近代/自然馆；节点含展厅、电梯、坡道、休息点、无障碍卫生间、无障碍车位、服务台。
- Dijkstra 寻路（电梯故障时自动剔除故障电梯、全程绕行备用电梯；双梯全停时跨层展厅安全跳过且不崩溃）。
- **到馆接续重算**：参观进行中故障时，从观众当前位置接续（保留已完成展厅为成果），并重算失效原因、预计延误、是否需工作人员推行、替代展区、线上讲解与参观收益（见下节）。
- 每段路线提示：**距离、最大坡度、步行/乘梯耗时、预计到达时间、休息点、无障碍卫生间位置、需要协助的动作**。
- 按体力调整步速与步行预算（轮椅 / 慢速 / 老人 / 不能久站），低体力路线自动插入休息点与卫生间途经点。
- 拥挤度按开馆双峰（10:30、14:30）+ 展厅热度确定性测算，并支持工作人员人工覆盖；**过度拥挤展厅自动避让**。
- 临时闭馆展区自动移出；闭馆时间/返回缓冲不足的展厅不排入。
- 轮椅库存、无障碍车位、讲解员/志愿者排班（技能：手语/慢速/轮椅协助、班次、请假、时段冲突、楼层接应位容量）统一核算并给出降级方案。

### 入馆当天（馆内平板工作台 `/ops`）
- **服务台**：核验预约、办理入馆、借出/归还轮椅（记录资产编号与时间）、确认车位、安排/人工改派讲解员或志愿者。
- **展厅工作人员**：在"今日接应任务看板"按时间看到每组观众的**预计到达时间、人数、是否轮椅、拥挤度与需要协助的节点**。
- **现场调度**：一键设置电梯临时故障、展区临时闭馆、展厅拥挤度、讲解员临时请假、轮椅报修/归库；**变更后所有相关预约的路线、排班、设备与提示自动重算**（路线版本递增并写入服务记录）。
- 支持处置：观众迟到、观众身体不适（自动缩减路线、加密休息）、陪同人临时增加、突发协助（坡道推行、电梯接应、医护联系、卫生间引导等自定义记录）。

### 观众已到馆 · 电梯故障后的路线重算（观众端 `/visit/:id` + 服务台 `/ops`）
观众**入馆、参观进行中**通往重点展厅的电梯停用时，系统不是简单取消服务，而是基于**观众当前位置**做接续重算，并在观众手机页与服务台同步呈现：
- **接续重算**：从服务台校正的当前位置（默认取最后已完成展厅）继续，已参观展厅标记"接续前已参观"作为成果保留，仅重排剩余路线，轨迹自动绕开故障电梯。
- **失效原因**：用观众能理解的语言说明（设备保护停用、改乘备用电梯、单梯候梯变久、双梯全停时无承载轮椅的垂直通道）。
- **可替代展区 / 保留重点展品**：对比新旧路线，列出保留的重点展厅、加排的同层替代展区、本次无法到达的展厅。
- **是否需要工作人员推行**：轮椅观众在单梯运行/坡道绕行时自动判定"需要接力推行"，并给出电梯口、坡道的协助说明。
- **预计延误时间**：按单梯候梯增加、厅内绕行、休息节奏重算新结束时刻与原计划的差值。
- **线上讲解补充**：无法到达的展厅自动推送同名"云端展厅"线上讲解（图文/短视频），休息区陪同观看。
- **观众三选一（结果服务台留存）**：① **调整参观顺序**（按新无障碍路线继续）；② **改期**（保留同规格预约与讲解权益，按电梯恢复后的全新一天重排路线）；③ **取消本次人工讲解**（保留无障碍路线与楼层定点协助，发自助讲解器）。
- **新参观收益**：页面明确列出"保留重点展品、已看展厅计入成果、缩短步行/加密休息、线上讲解补充、全程有人协助"，减少"服务被随意取消"的感受；再次发生新故障会重置上一轮决策并重新分析。
- 服务台可在平板端**推进已完成展厅、校正当前位置、代观众做选择并留存处理结果**（安排推行/接应/推送云端讲解），全部写入同一条服务记录时间线（`故障重算`、`处置留存`事件）。

### 同一条服务与服务延续（观众端 `/visit/:id`）
- 馆区平面图高亮实际路线（电梯、坡道、休息点、卫生间、闭馆/故障、拥挤点）。
- 完整分段路线时间线（距离、坡度、休息点、卫生间、预计到达）。
- 观众可手机自助报备迟到、身体不适、给服务台留言。
- **服务记录时间线**：预约前（book/排班/车位）、入馆中（核验、轮椅借还、路线调整、协助、突发）、参观后（归档、反馈偏好）全程留痕；反馈偏好用于"下次接待延续"。
- 数据通过 Zustand persist 保存在浏览器 localStorage，刷新不丢失。

## 目录结构

```
src/
  types.ts              领域模型（预约/路线/设备/人员/服务事件）
  data/museum.ts        馆区节点图、通道/电梯/坡道、展厅、库存、排班
  lib/planner.ts        路线规划引擎：寻路、拥挤度、库存/车位/排班约束、突发重算、到馆接续重算与 analyzeReroute
  store.ts              Zustand store：全链路动作（含接续重算/观众三选一/服务台留存）+ 持久化 + 演示数据
  components/           馆区平面图、路线时间线、电梯故障重算面板、通用 UI
  pages/                首页(手机端我的预约) / 预约 / 参观详情 / 馆内工作台
scripts/                规划场景断言、store 冒烟、SSR 渲染冒烟
Dockerfile / nginx.conf / docker-compose.yml   一键启动
```

## 本地启动

### 方式一：Docker 一键启动（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8080
```

多阶段构建：Node 22 构建静态产物 → nginx 1.27 托管（含 SPA history 回退），容器带健康检查。

### 方式二：本地开发（Node 22）

```bash
npm install
npm run dev          # http://localhost:5173 ，热更新
npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览生产构建
```

> 若本机 npm 缓存目录权限异常（EACCES），可指定本地缓存：
> `npm install --cache ./.npm-cache`

- 观众手机端：首页 `/`、预约 `/book`、参观详情 `/visit/:id`（可用浏览器 DevTools 切手机视口）。
- 馆内平板端：`/ops`（建议横屏/平板视口）。

## 验证方式

### 自动化验证（已全部通过）

```bash
npm run build     # tsc 严格类型检查 + Vite 构建
npm test          # 三个测试套件，共 125 项断言
```

- `test:scenarios`（58 项）：低体力全需求路线、普通观众全覆盖、单梯故障绕行、双梯全停降级、库存不足、迟到顺延、过度拥挤避让、手语请假降级、排班冲突换人、身体不适缩减、临时闭馆、车位约满、时间单调性，以及**到馆接续重算、接续分析（失效原因/延误/推行/收益）、双梯全停丢失展厅+线上补充、取消讲解自助路线**等。
- `test:store`（37 项）：建约→故障联动重规划→核验→借还轮椅→迟到→不适缩减→陪同人增加→突发协助→归档反馈，以及**参观中故障接续→观众三选一（调整顺序/改期/取消讲解）→服务台留存→新故障重置**的同一条服务全链路。
- `test:render`（30 项）：用 react-dom/server 渲染四个路由，校验关键字段（日期/人数/轮椅/手语/慢速/老人儿童/车位/久站、分段路线、坡度、休息点、卫生间、接应看板、服务记录、平面图），以及**故障重算面板（失效原因/延误/推行/收益/三选一）、处置留存结果**。

### 手动验证清单

1. 打开 `/book`，勾选"借用轮椅 + 慢速 + 老人 + 车位 + 不能久站"，观察右侧可行性预估随填写变化。
2. 提交预约，进入详情页查看平面图高亮与每段路线的**距离/坡度/休息点/卫生间/预计到达**。
3. 进入 `/ops`：
   - 点"**1号客梯 → 设为故障**"，回到详情页确认路线改走 2 号梯、版本升 v2、服务记录出现"路线调整"；
   - 点某讲解员"**设请假**"，确认相关预约自动改派并给出降级提示；
   - 连续点"**轮椅报修**"直到库存为 0，确认借用预约出现排队调剂提示；
   - 把自然探索馆拥挤度设为"过度拥挤 88%"，确认路线避让该厅；
   - 对选中服务设置"**迟到 30 分钟**""**身体不适**""**临时增加陪同 +2**"，确认接应时间顺延、展厅缩减、队伍人数更新；
   - 点"核验入馆 → 借出轮椅 → 开始参观 → 突发协助 → 归还轮椅 → 完成归档"，确认所有动作都出现在该服务的**同一条记录时间线**中。
4. **【本次新增】到馆电梯故障接续重算**（用演示数据"张女士"，其状态为参观中、已看完 B1 青铜特展）：
   - 在 `/ops` 点"**1号客梯 → 设为故障**"，打开张女士服务，确认出现"**③⁺ 参观进度与当前位置**"，可标记已看展厅、校正当前位置；
   - 打开观众端 `/visit/:id`，确认顶部出现红色"**路线已重新计算**"面板：**失效原因、预计延误、保留重点展厅、可替代展区、是否需要工作人员推行**齐全，"已参观成果保留"，并列出**新的参观收益**；
   - 分别体验三选一："**调整参观顺序**"按新路线继续；或重置后选"**改期**"（选日期/时间）确认状态变"已改期"、路线按电梯恢复重排；或选"**取消本次讲解**"确认陪同取消但无障碍路线保留；
   - 回到 `/ops`，在处置面板的"**服务台接手处理**"填写并留存，确认观众端出现"**服务台已留存**"结果，服务记录出现 `故障重算` 与 `处置留存` 事件；
   - 再把"**2号无障碍电梯也设为故障**"（双梯全停），确认楼上展厅丢失、推荐改期、提供**线上讲解补充**，且新故障会重置上一轮决策。
5. 归档后在详情页底部填写反馈，回到首页确认该偏好出现在历史服务记录中（供下次延续）。

## 已执行的验证结论

- ✅ `npm run build`：TypeScript 严格模式 0 错误，Vite 生产构建成功。
- ✅ `npm test`：58 + 37 + 30 = **125 项断言全部通过**。
- ✅ `npm run preview` 启动后 `curl http://localhost:5173/` 返回 `200` 与应用 HTML（preview 端口在 `vite.config.ts` 固定为 5173）。
- ⚠️ 当前开发环境**未提供 Docker 守护进程**，因此 Dockerfile/Compose **未能在本环境实际构建镜像**；构建流程（多阶段 + nginx SPA 回退）已按标准方式编写，请在装有 Docker 的环境执行 `docker compose up --build` 做最终确认。
- 说明：应用为纯前端演示，排班、拥挤度、库存为内置确定性模型与本地数据；真实接入时可将 `src/lib/planner.ts` 的输入与 `src/store.ts` 的动作替换为后端 API，页面与状态结构无需改动。
